# HTTP API

Every node serves one HTTPS API and the web UI on `web.address:web.port` (default port 8443). The web UI uses exactly this API, so anything you can click you can script. All paths are under `/api`, `/auth`, `/oauth`, `/.well-known` or `/mcp`; any other `GET` returns the web UI. Examples use `cloud.example.com` and a key in `$KEY`.

:::note
This page was written from reading the code. Only unauthenticated requests were tried against a running node: API paths answer `401` with JSON, and any other `GET` returns the web UI. {/* TODO verify: live check of write relay to the leader and remote-instance behaviour on a two-node cluster */}
:::

## Authentication

There are two ways in.

- **API key.** Send `Authorization: Bearer clk_<id>_<secret>`. An API key is always an admin. Only a hash is stored; the plaintext is returned once by `POST /api/keys`. The first key of a new cluster is called `bootstrap` and is printed to the log once.
- **Session cookie.** `POST /auth/login` with `{"key": "clk_..."}` returns the identity and sets the `cl_session` cookie (`HttpOnly; Secure; SameSite=Lax`). An OIDC login ([access and login](/docs/features/access-and-login)) sets the same cookie. The cookie is how browser `EventSource` streams authenticate, because they cannot send headers.

In the tables below, **Auth** means:

| Value | Meaning |
|---|---|
| none | Public. |
| user | Any signed-in caller: an API key or a session. |
| admin | An API key, or an OIDC session whose admin claim matches. A viewer gets `403` `admin role required`. |
| token | A secret token in the URL path. |
| internal | Node-to-node, signed with the cluster key. Not usable from scripts. |

A malformed `Authorization` header (for example `Basic ...`) is a `401` even if a valid cookie is also sent. The `Bearer ` prefix is optional on the dashboard API but required on `/mcp`.

```bash title="Check your key"
curl -s -H "Authorization: Bearer $KEY" https://cloud.example.com/auth/me
# {"subject":"...","username":"...","role":"admin","mcp_enabled":true}
```

CORS is permissive, so keep keys and cookies secret; do not rely on the browser's same-origin policy for this API.

## Which node answers

Send requests to any node. You do not need to know the leader.

| Request on a follower | Result |
|---|---|
| `GET` under `/api` | Answered from that node's replicated state. It may lag; compare `state_version` from `/api/status`. Live container, usage and daemon-log data comes from the node that owns it. |
| `POST`, `PUT`, `PATCH`, `DELETE` under `/api` or `/auth` | Relayed to the leader (method, headers and a body up to 32 MiB). The leader's status, headers and body come back to you. |
| `/auth/oidc/*` | Served locally, so login works from any node. |
| `/api/git-backup/webhook`, `/api/git-backup/webhook/internal-trigger`, any path containing `/internal/` | Served locally. |
| `GET /oauth/authorize` | `307` redirect to the leader. |
| `POST /oauth/token`, `POST /oauth/register` | Relayed to the leader. |
| `/mcp` | Relayed to the leader (body up to 5 MiB). |
| No leader known | `503`. |

:::info The not-leader 503 with Location
Older documentation says a follower answers a write with `503` and a `Location` header pointing at the leader. The current code relays the write instead, and never sends a `Location` header, so clients do not need to follow redirects. The error type `not the leader` still exists (status `503`) but is only built without a leader address.
:::

## Errors

An error is `{"error": "<message>"}`. Read only `error`; a `detail` field exists in the type but is never filled in.

| Status | Meaning |
|---|---|
| 400 | Bad request (validation failed, bad body). |
| 401 | Not authenticated. On `/mcp` it adds `WWW-Authenticate`. |
| 403 | Forbidden (for example `admin role required`). |
| 404 | Not found (for example `no instance <id>`). |
| 409 | Conflict (for example an update already in progress, a stale settings save, this node holds no cluster key). |
| 429 | Too many requests. |
| 503 | Unavailable or not leader. |
| 500 | Internal error. |

Two 503s are not JSON: the plain text `no cluster leader elected yet` (a follower with no known leader), and the JSON `could not reach the leader: ...` when the relay fails. Scripts that parse JSON errors must handle the plain-text one.

## Live streams (SSE)

Five endpoints stream `text/event-stream`. With curl add `-N`:

```bash title="Follow a container's logs"
curl -N -H "Authorization: Bearer $KEY" \
  "https://cloud.example.com/api/instances/vaultwarden.web.0/logs?follow=true&tail=50"
```

| Endpoint | Event | Data | Notes |
|---|---|---|---|
| `GET /api/events` | `state` | The redacted cluster state (no secret values) | Sent on connect, then whenever the state version changes (polled every 500 ms). |
| `GET /api/instances/events` | `progress` | `{instance_id, state, reason, step}`; `step` is `[n, m]` or null | First event per instance is its current value, then only changes (polled every 1 s). |
| `GET /api/instances/{id}/logs` | `stdout`, `stderr`, `error` | `{timestamp, text}` per line; `error` carries a message string | Query: `follow` (default false), `tail` (default 200), `since` (unix seconds). Without `follow` the stream ends after the tail. Relayed for remote instances. |
| `GET /api/instances/{id}/stats` | `stats` | `{cpu_percent, memory_used_bytes, memory_limit_bytes, network_rx_bytes, network_tx_bytes, io_read_bytes, io_write_bytes}` | One sample per tick until you disconnect. Relayed for remote instances. |
| `GET /api/nodes/{name}/logs` (admin) | `log` | `{seq, timestamp (unix ms), level, target, message}` | Query: `tail` (default 200, up to the 2000-line ring) and `follow` (default true). An unreachable node answers 503. |

### Internal routes

Paths containing `/internal/`, plus `/api/links/...`, are for nodes and the `clouduler` CLI. They are signed with the cluster key (HMAC over method, path, query, timestamp, nonce and body hash), accepted once within a time window, and cannot be called from a script. Examples are `/api/git-backup/pull`, `/api/git-backup/reconcile`, `/api/updates/internal/scan` and `/apply`, `/api/self-update/internal/restart`, `/api/instances/internal/*`, `/api/nodes/internal/*` and `/api/dns/internal-reconcile`. Do not expose them.

## Examples

```bash title="Deploy a stack"
curl -X PUT https://cloud.example.com/api/stacks/notes \
  -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d "{\"spec\": $(jq -Rs . < notes.yaml), \"configs\": {}, \"secrets\": {}}"
```

```bash title="Drain a node"
curl -X PATCH https://cloud.example.com/api/nodes/cirrus \
  -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{"availability": "drain"}'
```

```bash title="Cluster status from any node"
curl -s -H "Authorization: Bearer $KEY" https://cloud.example.com/api/status
```

## Quirks and gotchas

<Quirk title="API keys are always admin" severity="danger">
There is no read-only API key. For read-only access use an OIDC viewer account or a read-only MCP grant.
</Quirk>

<Quirk title="Reads on a follower can be stale" severity="info">
Compare `state_version` in `/api/status` between nodes to see how far behind a node is.
</Quirk>

<Quirk title="Webhook tokens are in the URL">
`/api/git-backup/webhook/{token}` and `/api/stacks/{name}/update-webhook/{token}` check a token in the path, not a header, and need no other login. Anyone with the token can call them. Rotate with the regenerate endpoint.
</Quirk>

<Quirk title="Self-signed certificate until ACME">
A node serves a self-signed certificate until a real one is issued for its address. Scripts that verify TLS will refuse it until then.
</Quirk>
