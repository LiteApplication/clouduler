# Nextcloud

Nextcloud is file sync, sharing and an office suite. This example uses the same seven containers as the Nextcloud All-in-One (AIO) project: an Apache front end, the Nextcloud app, PostgreSQL, Redis, notify-push, Imaginary for image previews and Collabora for documents. Talk, Whiteboard, OnlyOffice, ClamAV and full-text search are switched off, but their secrets are still referenced, so they must exist.

It is the biggest example, and the best one for seeing how Clouduler handles a multi-container app with many secrets and locked-down containers.

## What you'll learn

- **Nine secrets** exposed as environment variables, one of them under three different names.
- **`tmpfs` volumes** and `read_only: true` containers, plus `cap_add` and `cap_drop`.
- The same drive volume mounted read-only in some services and read-write in another, and **`colocate`** to keep them on one node.
- A **`redirect_regex`** middleware for the CalDAV and CardDAV discovery paths.
- A long `stop_grace_period` (the 600 second maximum) for a database.
- **Maintenance actions** that wrap `occ`.

## Prerequisites

**Cluster.** Networks `tailscale` (internal, domain `home.example.com`) and `wan` (egress). Drives `fast`, `apps` and `bulk`. See the [cluster prerequisites](/docs/examples#cluster-prerequisites).

**DNS.** `nextcloud.home.example.com`, reachable on the tailnet only. Your devices must resolve it to a node's tailnet address.

**Secrets.** All nine are referenced by the stack, so all nine must exist before the first deploy, even those for disabled features.

| Name | Used by | Suggested setting |
|---|---|---|
| `nextcloud_db_password` | The database (as a file), Nextcloud (`DATABASE_PASSWORD`, `PGPASSWORD`, `POSTGRES_PASSWORD`) | **Generate**, `alphanumeric`, `32` |
| `nextcloud_redis_password` | Redis and Nextcloud (`REDIS_HOST_PASSWORD`) | **Generate**, `alphanumeric`, `48` |
| `nextcloud_admin_password` | Nextcloud (`ADMIN_PASSWORD`), used once to create the first admin | **Paste string** with a password you will keep. A generated value cannot be read back. |
| `nextcloud_fts_password` | `FULLTEXTSEARCH_PASSWORD`. Full-text search is disabled. | **Generate**, `alphanumeric`, `32` |
| `nextcloud_imaginary_secret` | Imaginary and Nextcloud (`IMAGINARY_SECRET`) | **Generate**, `hex`, `64` |
| `nextcloud_turn_secret` | `TURN_SECRET`. Talk is disabled. | **Generate**, `hex`, `64` |
| `nextcloud_signaling_secret` | `SIGNALING_SECRET`. Talk is disabled. | **Generate**, `hex`, `64` |
| `nextcloud_recording_secret` | `RECORDING_SECRET`. Talk recording is disabled. | **Generate**, `hex`, `64` |
| `nextcloud_whiteboard_secret` | `WHITEBOARD_SECRET`. Whiteboard is disabled. | **Generate**, `hex`, `64` |

**Configs.**

| Name | Source file | Content |
|---|---|---|
| `nextcloud_disable_jit` | `./config/nextcloud_disable_jit.ini` | `opcache.jit=disable` |

**Volumes.**

| Volume | Mounted by | Notes |
|---|---|---|
| `fast/nextcloud-html` | Apache (read-only), Nextcloud (read-write), notify-push (read-only) | Application code and config tree. |
| `fast/nextcloud-db` | Database | PostgreSQL data directory. |
| `fast/nextcloud-redis` | Redis | Redis data. |
| `apps/nextcloud-db-dump` | Database (`/mnt/data`) | Destination for AIO's own database dumps. |
| `bulk/nextcloud-apache-data` | Apache (`/mnt/data`) | AIO's data directory for the front end. |
| `bulk/nextcloud-data` | Nextcloud (`/var/www/html/data`) | User files, the bulk of the storage. |

## Config files

```ini title="config/nextcloud_disable_jit.ini"
opcache.jit=disable
```

The Nextcloud container reads it as `/usr/local/etc/php/conf.d/zz-disable-jit.ini`, set by `target:`. It turns off the PHP JIT. Drop the config and the `configs:` entries if you do not need that.

## Walkthrough

- **`networks.tailscale.allowed`** lists only Nextcloud's own hostname: the stack may call its own route (Collabora fetches documents through it) and nothing else on the tailnet. **`wan: {}`** is unrestricted outbound for sign-in and app downloads. Only the Nextcloud container is attached to it.
- **Secrets as `env:`**. Each `source` and `env` pair exposes a secret as an environment variable. `nextcloud_db_password` appears three times under three names because three tools in the image read three different variable names. A secret exposed this way is visible to `docker inspect` on the node.
- **Volumes**. `:ro` mounts the same drive volume read-only in Apache and notify-push while Nextcloud mounts it read-write. `type: tmpfs` entries are in-memory mounts: lost on restart and never replicated. With `read_only: true`, they are the only writable paths besides the drive volumes.
- **`colocate`** on the Apache service pins it, Nextcloud and notify-push to one node, because they all use `fast/nextcloud-html`. Without it, the scheduler is free to place them on different nodes. See [Placement](/docs/features/placement).
- **`cap_add` and `cap_drop`**: each container drops `NET_RAW`. Imaginary adds `SYS_NICE`, Collabora adds the capabilities its sandbox needs.
- **`stop_grace_period: 600s`** is the longest the spec allows. The database and Nextcloud need time to finish on shutdown. `stop_signal: SIGINT` is PostgreSQL's fast shutdown.
- **Database actions**: `Checkpoint` plus `volume_sync.nextcloud-db.before` is the same pattern as in [Immich](/docs/examples/immich).
- **Proxy route**: `port: 11000` is the AIO Apache port, not 80. The `redirect_regex` middleware rewrites `/.well-known/carddav` and `/.well-known/caldav` to `/remote.php/dav` so mobile clients find the server. `permanent: true` makes it a 301 or 308.
- **Actions** wrap `occ`. `user: www-data` is the user occ expects. `Maintenance mode on` and `Repair` ask for confirmation.
- **Healthchecks** use a string `test: /healthcheck.sh`, which runs through a shell. The AIO images ship that script.

## Deploy

<UiCli>
<UiCli.Ui>

1. Open **Settings**, **Secrets and configs**. For each secret in the table, click **Create secret**, choose **Generate** (or **Paste string** for the admin password) and set the length and character set.
2. Open **Stacks**, **Deploy stack**, name it `nextcloud`, paste the YAML.
3. In **Bundled files**, fill `nextcloud_disable_jit` with `opcache.jit=disable`.
4. When the spec is valid and the secrets listed in **What it needs** exist (Settings, Secrets and configs), click **Deploy nextcloud**.

```bash
mkdir -p nextcloud/config && cd nextcloud
echo 'opcache.jit=disable' > config/nextcloud_disable_jit.ini
# save the YAML as nextcloud.yaml

gen() { tr -dc "$2" </dev/urandom | head -c "$3" | clouduler secret set "$1"; }
gen nextcloud_db_password        'A-Za-z0-9' 32
gen nextcloud_redis_password     'A-Za-z0-9' 48
gen nextcloud_fts_password       'A-Za-z0-9' 32
for s in imaginary turn signaling recording whiteboard; do
  openssl rand -hex 32 | clouduler secret set "nextcloud_${s}_secret"
done

clouduler stack deploy ./nextcloud.yaml
```

## First run

1. Open `https://nextcloud.home.example.com` from a tailnet device and sign in as `admin` with the password you set for `nextcloud_admin_password`. The first start can take a few minutes while Nextcloud installs.
2. In the administration overview, look for warnings, then run **Add missing indices** from the **Service actions** panel on the `nextcloud-aio-nextcloud` container page.
3. After copying files into `bulk/nextcloud-data` by hand, run **Scan files** so Nextcloud sees them. Switch on **Maintenance mode on** for bulk file operations, then **Maintenance mode off**.
4. Collabora is running, but Nextcloud's Office app still needs its connector pointed at the Collabora host. Check the Office settings after the first start.

## Quirks

<Quirk title="Nine secrets, even for features you do not use" severity="info">
Talk, Whiteboard, OnlyOffice and full-text search are off, but the Nextcloud container references their secrets. A missing secret stops the container that mounts it from starting, so create all nine. The unused ones are inert.
</Quirk>

<Quirk title="One domain in many places" severity="warn">
`NC_DOMAIN`, `OVERWRITEHOST`, `server_name`, the Collabora `aliasgroup1` and font URL, and the route all carry the same host. Change them together when you change domain.
</Quirk>

- **No upload cap on the route.** `PHP_UPLOAD_LIMIT` and `APACHE_MAX_SIZE` are 16 GB, and the route sets no `max_body_size`, so the proxy does not cap uploads either. Add one if you want a limit.
- **Memory.** Nextcloud gets 2G and the database 512M. Raise the database limit if you have many users, and keep `PHP_MEMORY_LIMIT` below the container limit.
- **`COLLABORA_ENABLED` is `no`.** The Collabora container runs and Apache proxies to it, but Nextcloud's own switch is off, so you configure the connector manually.
- **Pin the images.** The AIO images use `latest`. Pin tags once it works, and move them together.
